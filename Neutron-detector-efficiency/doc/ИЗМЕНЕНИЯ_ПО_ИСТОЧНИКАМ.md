# Изменения: остановка одного источника и эффективность по распадам

## Физическая единица статистики

`G4Event` остаётся контейнером для `Settings::N_IONS` независимых исходных
ядер Cf-252 (GEANT) или актов деления Cf-252 (FREYA). Он не является единицей
эффективности.

Каждому исходному ядру/акту деления назначается `sourceID = i`, где `i` — индекс
цикла `N_IONS` внутри текущего `G4Event`. Все первичные продукты этого источника
и все их потомки сохраняют тот же ID.

Правильная эффективность:

```text
DecayEfficiency = DetectedDecays / TotalDecays
```

- `TotalDecays` — число всех исходных актов деления Cf-252.
- `DetectedDecays` — число уникальных sourceID, от которых хотя бы один нейтрон
  вызвал реакцию `3He(n,p)3H` в `He3Gas`.
- Несколько реакций от одного sourceID увеличивают `DetectedDecays` только один раз.
- `DetectedEvents` и `EventsWithDetectedDecays` оставлены только как диагностические
  счётчики и не входят в формулу эффективности.

В расчёте предполагается, что GEANT использует пользовательскую таблицу распада,
принудительно задающую спонтанное деление Cf-252 с вероятностью 100%. В FREYA один
вызов генератора соответствует одному акту спонтанного деления.

## Изменённые файлы

1. `source_track_information.h` — типы пользовательской информации для первичной
   частицы, трека и метаданных FREYA-источников в событии.
2. `primary_generator.cpp` — сохраняет исходный цикл `N_IONS` и распределение
   координат; каждому исходному ядру или набору FREYA-продуктов назначает один ID.
3. `geant4_decay_generator.h/.cpp` — принимает `sourceID` и прикрепляет его к
   первичному ядру Cf-252.
4. `tracking_action.h/.cpp` — передаёт ID от первичного трека всем вторичным трекам
   в `PostUserTrackingAction`; перед началом очередного трека проверяет, не был ли
   его источник уже зарегистрирован как обнаруженный.
5. `stacking_action.h/.cpp` — отбрасывает новые треки (`fKill`), если их источник
   уже дал первую реакцию. Остальные источники события не затрагиваются.
6. `event_action.h/.cpp` — хранит множества посчитанных, обнаруженных и остановленных
   sourceID в пределах одного `G4Event`; каждый sourceID учитывается не более одного
   раза в каждом счётчике.
7. `stepping_action.cpp` — распознаёт распад Cf-252 для знаменателя и реакцию
   `3He(n,p)3H` для числителя; при первой реакции помечает только соответствующий
   sourceID и убивает текущий нейтрон.
8. `run_action.h/.cpp` — считает `TotalDecays`, `DetectedDecays`, а также вспомогательные
   диагностические величины; вычисляет эффективность по распадам.
9. `main.cpp` — регистрирует `TrackingAction` и `StackingAction`; в режиме GEANT
   подключает пользовательскую таблицу распада Cf-252.
10. `settings.h` и `data/README.txt` — задают путь к пользовательской таблице GEANT.
11. `run_scan.C` — сохраняет `TotalDecays` и `DetectedDecays` в ROOT.
12. `plot_efficiency.C` — рассчитывает `DetectedDecays / TotalDecays` и биномиальную
    статистическую погрешность.
13. `compile.sh` — включает новые файлы действий в сборку.

## Что происходит после первой реакции конкретного источника

1. `SteppingAction` находит нейтрон, который в объёме `He3Gas` создал одновременно
   протон и тритон.
2. Из `SourceTrackInformation` извлекается ID исходного ядра/деления.
3. `EventAction::MarkDetectedDecay(sourceID)` добавляет ID в множество обнаруженных
   источников. Повторная реакция от того же ID ничего не увеличивает.
4. Этот ID попадает также в множество остановленных источников.
5. Текущий нейтрон получает `fStopAndKill`.
6. Новые дочерние треки этого источника отклоняются в `StackingAction` через `fKill`.
7. Треки этого источника, уже находившиеся в очереди, получают `fStopAndKill` в
   `TrackingAction::PreUserTrackingAction` до своего первого шага.
8. Треки с другими sourceID продолжают транспортироваться.

`AbortEvent()` и `AbortRun()` не вызываются. Все `N_IONS` источников в событии
сохраняются; не завершается ни весь `G4Event`, ни весь запуск.

## Подсчёт знаменателя

- GEANT: `SteppingAction` регистрирует sourceID при выполнении процесса
  `RadioactiveDecay` на ядре Cf-252. Поэтому пользовательская таблица должна
  оставлять только спонтанное деление.
- FREYA: ID каждого выполненного акта деления записывается в `SourceEventInformation`
  во время `GeneratePrimaries`; `EndOfEventAction` регистрирует все такие ID, даже
  если у конкретного результата не оказалось транспортируемых первичных частиц.
- `RegisterDecay` защищён множеством `fCountedDecaySources`, поэтому один источник
  не может попасть в знаменатель дважды.

Ожидаемое число актов деления для стандартного запуска:

```text
ExpectedDecays = processedG4Events * Settings::N_IONS
```

`RunAction` печатает ожидаемое и фактически зарегистрированное количество отдельно.
Если они не совпали, это диагностическое предупреждение; эффективность всё равно
считается по фактически зарегистрированным `TotalDecays`, а не по предполагаемому
значению.

## ROOT-анализ

`run_scan.C` сохраняет ветви:

- `TotalEvents` — число событий Geant4;
- `TotalDecays` — число актов деления;
- `DetectedDecays` — число уникальных актов деления, продукты которых дали реакцию;
- `BornNeutrons` — диагностический счётчик;
- `DetectedEvents` — диагностическое число G4Event хотя бы с одной реакцией.

`plot_efficiency.C` использует только `DetectedDecays` и `TotalDecays`:

```cpp
const double efficiency =
    static_cast<double>(detectedDecays) / totalDecays;

const double error = std::sqrt(
    efficiency * (1.0 - efficiency) / totalDecays
);
```

После обновления схемы ROOT необходимо заново выполнить `run_scan.C`, а затем
`plot_efficiency.C`. Старый `simulation_results.root` не содержит новых ветвей.
